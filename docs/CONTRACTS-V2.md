# Taka Plan v2 contracts (Stage 0, 31 Oct 2026)

What every v2 slice codes against. Read with [ARCHITECTURE.md](ARCHITECTURE.md), [TOOLING.md](TOOLING.md) and the PRDs ([insurance](PRD-insurance.md), [allocation](PRD-allocation.md), [retirement](PRD-retirement.md)).

## Countries

- **Data:** `packages/engine/src/data/countries/<CC>.json` (one `CountryProfile` each) + `index.json` (`CountryIndexEntry[]`) + `_regions.json` (`RegionDefaults`). Written by the research workflow; Stage 1 slices use the fixtures in `packages/engine/src/fixtures/countries.ts` (`FIXTURE_BD`, `FIXTURE_IN`, `FIXTURE_US`).
- **Types:** `packages/engine/src/country/types.ts`. Every researched figure is a `CountryField {value | valueJson, status: sourced|assumption|missing, sourceName, sourceUrl, asOf, note}`.
- **Which keys a country sets:** `COUNTRY_FIELDS` / `COUNTRY_FIELD_KEYS` in `country/fields.ts`. `BANGLADESH_ONLY_KEYS` stay in the snapshot but the UI hides them outside BD (`snapshot.country.notApplicable`).
- **Validation:** `assertCountryProfile(x, unitsFrom(seed.rows))`, `assertCountryIndex(x)` (`country/validate.ts`).
- **Overlay:** `withCountry(baseSnapshot, profile, { regions, bdUsdRate })` (`country/overlay.ts`) returns the snapshot every calculator reads. BD = identity. It sets `snapshot.country: CountryContext` (currency, rounding steps, unavailable product slots, local product names, fallback keys, institutions). Never run `assertSnapshot` on an overlaid snapshot (country rates may be negative).
- **Rounding:** `roundingFor(snapshot)` gives the currency's steps (BDT 500/100/100/1). Modules must round with these steps, never the taka constants, once the country runtime lands (`roundMoney(x, kind, steps)`).
- **Product slots:** the `Instrument` ids are generic slots (`fdr_1y` = 1-year term deposit, `dps` = recurring deposit, `sanchayapatra_5y` = government savings certificate, `tbill_91d`, `tbond_5y`, `tbond_10y`, `equity_fund`, `gold`, `savings_account`, `fdr_3m`). Candidate lists must drop `snapshot.country.unavailable`; the UI shows `snapshot.country.instrumentNames[slot]` (local name) or the generic term.
- **D1:** `migrations/0004_countries.sql` (`country_versions` with per-country draft/publish and `meta` JSON, `country_fields`, `change_log.country`). Interface: `lib/server/country-repo.ts` (`CountryRepo`). The country seed migration is `0006_seed_countries.sql` (0005 is `0005_rates_plan_v2.sql`), generated from the JSON files.
- **API:** `GET /api/countries/:code` answers `{ version, status: "published", profile }` (`StoredCountry`), which `lib/country/loader.ts` `parseCountryBody` reads (a contract test in `server/api/countries/countries.test.ts` feeds the real handler output to it). There is no public list route; `GET /api/admin/countries` is the admin list.
- **Server limits** (`lib/server/country-clean.ts`, on top of the engine validator): admin meta patches allow only the patchable keys, the ten instrument slots and the eight institution keys, each with typed, known properties; names ≤ 100 characters, sources/URLs/institution names ≤ 300, notes ≤ 1,000; `researchedAt` ≤ today + 1 day and `asOf` ≤ today + 1 year, both real dates; JSON figures are reduced to their shape's keys; a profile may not pass 48 KB serialised. Publishing also runs `withCountry` + `computePlan` for the three sample profiles and refuses the draft (400 `INVALID_DRAFT`) when any throws.
- **Remote migrations for v2, in order:** `0003_rates_m2_m6_m7`, `0004_countries`, `0005_rates_plan_v2`, then `0006_seed_countries` (production has applied only 0001 and 0002; see [DEPLOY.md](DEPLOY.md#remote-migrations-before-deploying-v2)).

## Rates

- 104 rate keys (`RATE_KEYS` in `rates.ts`); 39 new ones for M2, M6 and M7 in `rates.seed.json` with Bangladesh values and sources. JSON rows have shapes in `rates-json.ts` (`JSON_SHAPES`), checked by `assertSnapshot` and `assertCountryProfile`.
- Migrations: `0002` is frozen (production applied it). `0003_rates_m2_m6_m7.sql` and `0005_rates_plan_v2.sql` add the new rows to the published and draft versions. All are generated by `npm run rates:gen-seed` from `ROW_BATCHES` in `scripts/gen-seed-migration.mjs`. 0003 and 0005 are not applied remotely yet, so new v2 rows go into the 0005 batch (`PLAN_V2_KEYS`), never a new file. `/api/health` reports `"db":"invalid-snapshot"` with `"reason":"rates table missing rows: …"` while the remote table lacks them.
- New rows asOf ≤ 2026-10-30 and nextReview > asOf (rates.test.ts).

## Modules

- Contracts with formulas in the file headers: `m2/types.ts` (insurance & health), `m6/types.ts` (asset allocation), `m7/types.ts` (retirement & family). Stubs: `computeInsurance`, `computeAllocation` (+ `riskProfileFor`, `allocationWeights`), `computeRetirement`.
- Pattern: same as M1–M5 (validate with `assertInput`, `createExplain`, round once, `explain` on the result, every step id in `M*_STEP_IDS`, note/check/option keys in their tuples).
- `PlanInput` gained `m2? m6? m7?` (full inputs) besides the explicit hooks `insurance`, `allocation`, `retirement`; `Plan` gained `insurance? allocation? retirement?` results; `BucketId` gained `"retirement"`, `BucketModule` gained `"m6"`; new keys `plan.reason.retirement`, `plan.reason.future`, `plan.next.insurance|retirement|allocation`.
- Explain input names: names ending in rate/inflation/tax/share (or nominal/real/afterTax) show as percent, ending in months/years/count as numbers, everything else as money (`components/explain/formatInputs.ts`). Use `ageYears`, `scoreCount`, `multipleCount`-style names or extend `NUMBER_NAMES` there.

## Store (lib/store)

- `TakaData` v2: `country`, `m2`, `m6`, `m7` (`M2State`, `M6State`, `M7State`), `drafts: Draft[]`; persisted under the old key `taka-plan.v1` with `version: 2` and `migrateState` (v1 → v2 keeps every answer, country BD).
- Actions: `setCountry`, `setM2`, `setM6`, `setM7`, `startOver()`, `openDraft(id)`, `renameDraft(id, name)`, `deleteDraft(id)`. Draft rules in `lib/store/drafts.ts` (hash of normalised answers; identical answers refresh, never duplicate; empty answers never saved; max 20).
- A new persisted field must be added to both `partialize` (store.ts) and `pickData` (usePlan.ts).

## Languages

- 12 locales: `locales` and `LOCALE_META` (native name, dir, Intl tag) in `lib/i18n/config.ts`, equal to the engine's `LOCALES`. `ar` and `ur` are right-to-left (`<html dir>` set by `HtmlLang`).
- Dictionaries: write every new key in `en/*` and `bn/*`. The ten other locales are `= en` placeholders until the translation stage; do not edit them in Stage 1.
- Money in UI: call `useFormat().money(...)` (today an alias of `taka`; the country runtime makes it currency-aware). Never call `taka` in new code.
- Cookies: `tp_locale`, `tp_country` (`COUNTRY_COOKIE`). URL prefix regex: `LOCALE_PREFIX`.

## Stage 1 rules

- Work only in the files your slice owns; if you need a shared change, make the smallest one and say so in your report.
- Frozen in Stage 1 unless your slice owns it: `package.json`, lockfile, `tsconfig*`, `vite.config.ts`, `vitest.config.ts`, `lib/store/types.ts`, `lib/store/store.ts`, `lib/i18n/config.ts`, `packages/engine/src/index.ts`, `packages/engine/src/rates.ts`, `rates.seed.json`, `country/types.ts`, the module `types.ts` files.
- Node: `export PATH="$HOME/.nvm/versions/node/v24.22.2/bin:$PATH"` (do not source nvm.sh in worktrees). Before finishing: `npx tsc --noEmit`, `npx tsc -p packages/engine/tsconfig.json --noEmit`, `npx vitest run`.
